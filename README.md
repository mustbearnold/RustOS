# RustOS

RustOS is a new Rust-first operating-system project whose long-term target is to replace CachyOS as a daily-use desktop operating system. The repository started empty, so the first milestone establishes the boot path instead of pretending that a complete Linux distribution can be replaced in one commit.

The intended development model is autonomous daily iteration by the configured GPT developer, with one bounded vertical slice per run, reproducible host/QEMU evidence, and direct commits on `main`; the execution contract and its limits are recorded in [AUTONOMY.md](AUTONOMY.md).

The current filesystem lifecycle includes persistent regular-file `unlink`/`rename`, stable open-file identities that survive both operations, and safe empty-directory `rmdir`, with VFAT long-name cleanup, deferred FAT-chain release, and directory-slot reuse covered by host tests plus BIOS and partitioned-UEFI shell proofs.

The current milestone is a real `no_std` x86_64 kernel plus a Rust `no_std` userland. The Rust bootloader loads it on BIOS or UEFI; the kernel owns physical memory, a 2 MiB virtual heap, bounded per-process anonymous `mmap`/`munmap` mappings with virtual-range reuse, physical-frame reclamation and reuse, and fork cloning, interrupts, ACPI, PCI capability discovery and MSI routing, ATA PIO/AHCI/NVMe/FAT/VFS storage including FAT32, bounded persistent-file creation and growth, interrupt-backed AHCI and NVMe command completion with polling fallbacks, e1000/e1000e DMA with ARP, DHCP, and external IPv4/UDP, modern PCI virtio-net feature negotiation with split-queue DMA, interrupt-backed RX/TX completion, and boot-time DHCP, a bounded PCI xHCI host-controller path with boot-protocol HID keyboard or mouse enumeration, interrupt-IN reports, and MSI-X/MSI completion notification, SMP startup, a persistent framebuffer text console, a validated userland graphics ABI with compositor ownership, unified USB/PS/2 keyboard and mouse input events with a ring-3 event ABI and interactive cursor, a retained multi-process window surface ABI with explicit z-order, click-to-raise focus, and focused-client keyboard routing, and a preemptive scheduler. Ring-3 programs enter through a real DPL3 `int 0x80` ABI with `getpid`, `yield`, `spawn`, root-only `spawn_as` plus allowlisted `spawn_privileged`, trusted caller-credential retrieval for privileged helpers, `getcredentials`, status-returning `waitpid`, console fd 0/1, file handles, threads, `exec`, `fork`, anonymous `mmap`/`munmap`, bounded UDP send/receive, hardware capability snapshots, network configuration and interface enumeration, framebuffer info/ownership/rectangle/text operations, keyboard/mouse event reads, window create/draw/text/present/destroy/compose/focus-event operations, nonblocking pipe reads, redirected stream inheritance, and `exit`. Process credentials propagate across fork and ordinary spawn; privileged transitions preserve the unprivileged requester identity. Shell mode runs as UID/GID 1000, can read mode-appropriate system files, can write only under `/home/user`, and is denied system-file writes. The filesystem-backed userland now includes Rust `init`, `sh`, `service`, `worker`, `cat`, `replaced`, `restart`, `pkg`, `admin`, `login`, `shell-login`, `desktop`, `terminal`, `window`, `window-secondary`, `vm`, `passwd`, `useradd`, and `lock` programs. The image builder and QEMU runner are also Rust programs.

The kernel now owns generic PCI playback paths for both AC'97 and Intel HDA: it claims typed I/O or MMIO BARs, enables bus mastering, discovers an HDA codec's audio function group/DAC/output pin through codec verbs, generates a stereo 48 kHz Rust tone in DMA pages, programs the controller buffer descriptors, and starts the output stream without a host audio library in the guest. HDA is preferred when both controllers are present, with AC'97 as the fallback.

The modern networking boundary now also includes a pure-Rust PCI virtio-net driver for QEMU's non-legacy device. It parses vendor-specific PCI regions, negotiates `VIRTIO_F_VERSION_1` and the MAC/status features, configures bounded RX/TX split virtqueues with physical DMA pages, arms a shared MSI-X queue-completion vector with polling fallback, and performs a real DHCP discover/request/ack exchange through QEMU user networking. A bounded Rust network manager retains every DHCP-ready virtio/e1000 interface, selects virtio as the default route with a deterministic e1000 fallback, schedules DHCP renewal at the lease midpoint with bounded retry, and routes `SYS_NET_INFO`, `SYS_NET_SEND`, and `SYS_NET_RECEIVE` through that route. `SYS_NET_INTERFACES`/`net interfaces` expose each interface's MAC, lease, address, route metric, and state, while `SYS_NET_RENEW`/`net renew` exercise an immediate renewal transaction across every managed NIC; ARP gateway resolution and external IPv4/UDP remain in the selected driver.

The storage boundary now carries one bounded POSIX `newc` initramfs (`INITRD.CPI`) inside the FAT root. The kernel validates its record headers, path components, trailer, entry count, and 512 KiB archive bound, then exposes the nested regular files through the catalog. It also mounts the FAT runtime filesystem with nested FAT12/FAT16/FAT32 directories, bounded ASCII VFAT long names with collision-safe short aliases, bounded `mkdir`, recursive snapshots, streaming disk-backed file creation/growth, seekable file handles, in-place truncate/extension with FAT-chain release and zero-fill semantics, and persistent regular-file `unlink`/`rename`; mutable files remain bounded by FAT's 32-bit directory size field and available clusters. Each image carries `/RUSTOS.ST`; the kernel toggles its `boot=0`/`boot=1` record, writes sectors through the selected block transport, and reads the result back before starting userland. The service and worker open `/etc/rustos/config.txt`, read its `cfg=` prefix, and write that user-originated data to the serial console.

The package boundary now carries a bounded Rust-owned `RREP3` repository at `/RUSTOS.REP`. The host image builder signs its fixed versioned index and embedded `RPKG1` payloads with rotated Ed25519 key `RUSTKEY2`; the built-in `RUSTKEY1` root authenticates that rotation certificate. `/bin/pkg` verifies the chain, persists the accepted key at `/VAR/PKG/TRUSTED`, validates SHA-256 package digests and manifests, resolves `HELLO -> BASE`, and stages HELLO v1, v2, and v3 under `/VAR/PKG`. The activation marker is committed last, while `/VAR/PKG/HISTORY` retains three generation IDs and `/VAR/PKG/PREVIOUS` keeps the immediate rollback target. `pkg` installs the newest generation, `pkg update` advances it, `pkg rollback` switches back through the staged dependency closure, and `pkg recover` re-stages the first verified generation after an invalid activation marker. `pkg sync` sends a repository request over the kernel's ARP/IPv4/UDP path and verifies the received signed repository before applying it. The Rust QEMU runner provides the development repository endpoint with `--network`; the installer can copy a selected BIOS/UEFI image or create a fresh GPT/ESP/FAT32-root layout with a validated 64 MiB–128 GiB RustOS root directly on a regular-file or block-device target, with partition-hash and readback verification.

The shell reaches protected operations through the fixed-request `/sbin/admin` helper: `sudo pkg install|update|rollback|sync|recover` and `sudo state set` run as root only after the caller's password and persisted account role are checked. The first configured account is stored as an administrator for compatibility with legacy records, while `useradd` explicitly creates either administrator or ordinary-user accounts; root remains allowed, and ordinary users receive an explicit denial. Arbitrary paths cannot be elevated and ordinary UID/GID 1000 writes remain denied.

PID 1 is now a config-driven Rust userland supervisor at `/sbin/init`: it opens `/etc/rustos/init.cfg`, reads bounded NUL-separated `path|retries` records with an optional `|uid|gid` identity, and starts `/bin/service`, `/bin/worker`, and `/bin/restart`. The runtime gate requires the complete 44-byte config read and verifies that a failed service status is observed, retried once, and recovered before PID 1 exits successfully; shell images launch a root-owned `/sbin/shell-login`, which performs the same first-boot account setup as the desktop login and then starts the interactive shell as UID/GID 1000.

Desktop images now start a root-owned `/sbin/login`, which reads the bounded account records, rejects invalid credentials, and launches `/bin/desktop` through the existing root-only `spawn_as` boundary as the authenticated UID/GID. On first boot it reports that setup is required, collects a new username and password without echoing the password, writes the fixed-size account store under `/VAR/RUSTOS/ACCOUNTS`, and rereads it before accepting a session; later boots load that persistent store. Images no longer carry a known default password. `/bin/passwd` changes the authenticated user's password through a fixed-format request to root-owned `/sbin/admin`; `useradd` requires the current administrator password, prompts for `user` or `admin`, and persists the selected role, `/bin/lock` establishes a password-unlock boundary with retry handling, and graphical password entry is masked. The bounded parser accepts up to four distinct records, migrates legacy records by preserving UID 1000 administrator behavior, and new users receive matching `/home/<uid>` workspaces. The account proof verifies first-boot account setup, account creation, per-UID desktop handoff, password masking, lock/unlock, old-password rejection, new-password relogin, non-administrator privileged denial, persistent reload, logout, and client reaping across first and second BIOS and partitioned-UEFI boots; the role proof creates a secondary administrator and verifies role-aware privileged authorization on both firmware paths.

The process boundary now also supports catalog-backed `exec`: `/bin/service` resolves `/bin/replaced`, loads it into a fresh user root, closes its non-console file handles, and resumes under the same PID. Runtime evidence keeps `/bin/service` as the process origin, reports `/bin/replaced` as the current executable with `execs=1`, observes the replacement message, and verifies the replacement exits successfully.

The same process boundary now supports real `fork`: `/bin/service` snapshots its interrupted user continuation, deep-copies the user address space and handle table into a new child, resumes the child after the syscall with return value `0`, observes its exit status `17`, waits for it in the parent, and then continues into `exec`. BIOS/UEFI proofs require the separate child root and parent-side status wait before the service replacement completes.

The virtual-memory boundary now exposes bounded anonymous `mmap`/`munmap` through the ring-3 ABI. `/bin/vm` writes and reads three mapped pages, forks and validates the child's deep-cloned pages, unmaps them, and requires the allocator to reuse the released virtual range. It then performs 128 cycles of 256-page writable mappings, readback, unmapping, and physical-frame reuse; BIOS and partitioned-UEFI `--vm-proof` runs require the complete lifecycle marker after the normal page-table and FAT/VFS boot path. Process teardown now reclaims ELF, stack, anonymous, private page-table, and root frames on both `exec` replacement and exit; the runtime emits `address_spaces_reclaimed=true` while a monotonic address-space ID keeps fork/restart isolation proofs valid even when physical roots are reused.

## Build and boot

The process-composition boundary now carries bounded anonymous 4 KiB pipes with reader/writer lifetime tracking. `SYS_SPAWN` can redirect child fd 0 and fd 1 to inherited pipe endpoints, `/bin/sh` supports the bounded `worker | cat` pipeline (plus a `pipe` builtin), and `/bin/cat` exits only after observing pipe EOF. BIOS and partitioned-UEFI `--pipe-proof` runs require producer output, redirected children, clean EOF reaping, and zero exit status from both children.

The desktop now starts `/bin/terminal` as its primary client after login. The terminal owns a redirected `/bin/sh` child, uses nonblocking pipe reads so keyboard and repaint events continue while the shell is idle, forwards line editing and commands through the focused window, and renders shell output inside the retained window surface. The native top bar also exposes a `LOG OUT` control that closes both clients, waits for their exit statuses, releases framebuffer ownership, and returns to the root-owned login loop. `--terminal-proof` completes first-boot account setup when needed, rejects a bad password, verifies desktop and shell UID/GID 1000 inheritance, injects `help` and `id`, and verifies the exit command and child reap through BIOS and partitioned-UEFI guests. `--logout-proof` clicks the graphical control and requires the same orderly teardown plus a ready next-login boundary on BIOS and partitioned UEFI.

The shell now starts as UID/GID 1000 in a persistent `/home/user` workspace, exposes Rust `SYS_GETCREDENTIALS`, `SYS_PATH_INFO`, `SYS_SEEK`, `SYS_TRUNCATE`, `SYS_UNLINK`, and `SYS_RENAME` ABIs, carries a bounded current directory through `cd` and `pwd`, resolves `.`/`..` and relative paths for `ls`, `mkdir`, `touch`, `write`, `append`, `truncate`, `rm`, `mv`, and `cat`, lists direct directory entries from the persistent FAT catalog, and launches filesystem-backed Rust programs with `run <path>` using inherited stdio and synchronous exit status. Initramfs modes are retained: the shell can read ordinary system files and execute mode-appropriate programs, but non-root writes and directory creation are confined to `/home/user`. `sudo pkg ...` and `sudo state set` use only the allowlisted fixed-request `/sbin/admin`, prompt for the current administrator password, and preserve the caller identity across the root transition. `--shell-proof` types a complete first-boot setup, identity, create, navigate, write, seek/append, shrink/extend, rename/read/remove, list, protected-read, denied-system-write, wrong-password denial, authorized state, authorized package, external-launch, and parent-directory sequence and validates the captured framebuffer on BIOS and partitioned UEFI.

The secondary desktop client is now a storage-backed file browser: it reads the bounded `SYS_LIST_FILES` catalog snapshot, renders live filesystem entries, and refreshes the snapshot on `R`. Strict `--desktop-proof` runs require the compositor, both clients, the storage snapshot marker, focus activity, and a valid captured framebuffer on BIOS and partitioned UEFI.

The desktop image carries `/bin/cat`, `/bin/terminal`, and `/bin/window-secondary` as filesystem-backed Rust ELFs alongside the existing supervisor, service, worker, package, desktop, window, and VM programs.

The graphics boundary now also has a real modern PCI `virtio-gpu` path. The kernel negotiates the version-1 virtio interface, allocates a bounded 2D resource with fragmented-DMA backing, attaches it to scanout 0, and transfers and flushes compositor frames from the firmware framebuffer. `--virtio-gpu-proof` requires the guest driver, resource, scanout, transfer, desktop, and captured-frame markers on BIOS and partitioned UEFI. This is a GPU-backed scanout transport; the compositor still rasterizes its retained scene in Rust, and Wayland protocol compatibility remains future work.

Boot now records typed PCI role counts, the primary display identity, framebuffer geometry, and the selected graphics backend. `SYS_HW_INFO` and the shell's `hw` command expose the same bounded report to userland. A normal firmware framebuffer is explicitly reported as `backend=firmware-framebuffer compositor=rust-cpu-raster acceleration=unavailable`; QEMU's proof path reports `virtio-gpu` scanout transport. This is the hardware truth needed for the Ryzen 7 5800X/RTX 5070 target: firmware display output and the native Rust compositor can be brought up first, while a native NVIDIA driver and GPU-accelerated compositor remain unfinished.

On modular Arch/CachyOS QEMU packages, install the `qemu-hw-display-virtio-gpu` and `qemu-hw-display-virtio-gpu-pci` modules before running the virtio-gpu proof. A user-local module directory can be selected with `QEMU_MODULE_DIR`.

`build` writes normal BIOS/UEFI images plus shell, desktop, and recovery images, as well as partitioned UEFI variants. `run bios --smp 2` boots a two-vCPU guest and verifies the page-mapping lifecycle, PCI inventory and typed hardware snapshot, ATA PIO sector reads and writes through `BlockDevice`, MBR/GPT partition discovery, FAT12/FAT16 geometry, the bounded `INITRD.CPI` newc archive and nested-path catalog, the persistent `/RUSTOS.ST` write/readback, kernel ELF access through the VFS boundary, all nineteen filesystem-backed Rust userland ELFs, e1000 BAR and DMA ring setup, ACPI/IO-APIC interrupt routing, an interrupt-driven Ethernet transmit/receive loopback through `NetworkInterface`, IPv4 and UDP parsing plus checksum validation on the received frame, AP startup, timer-driven kernel-task scheduling, PID 1 registration, ring-3 `getpid`/`yield`/`spawn`/status-returning `waitpid`/console/file/thread/`exec`/`fork`/`mmap`/`munmap`/`exit` syscalls, per-process handle allocation and shared-address-space thread stacks, user-memory validation, distinct address-space IDs with recyclable physical roots, complete process address-space reclamation, userland serial messages, successful file and thread lifecycle counts, fork status propagation, restart-policy status propagation, and repeated timer-driven entries into the children and their helper threads. QEMU's serial output is the first observable system console; stop it with `Ctrl-C`.

`run bios --shell` selects a shell-only `/etc/rustos/init.cfg`. On a fresh image, `/sbin/shell-login` asks for the first username and password before starting the UID/GID 1000 shell; no credential is baked into the image. After the prompt appears, type commands such as `help`, `id`, `whoami`, `ls`, `ps`, `hw`, `net`, `cat /etc/rustos/config.txt`, `mkdir work`, `write note hello`, `grow`, `truncate large.bin 65536`, `append large.bin tail`, `truncate large.bin 131072`, `mv note renamed-note`, `cat renamed-note`, `rm renamed-note`, `open-proof`, `sudo state set`, `sudo pkg install`, `run /bin/replaced`, `uname`, `echo hello`, and `exit`. The shell can inspect system files but its UID/GID 1000 permission boundary intentionally denies writes under `/etc` and `/VAR`; only the fixed-request `/sbin/admin` helper can perform the documented package and state operations. `sudo` asks for the current administrator password and rejects both a wrong password and non-administrator account callers. Input can arrive from the serial console, the emulated USB HID keyboard, or the PS/2 fallback; `run bios --shell --keyboard-proof` injects `net` and `exit` through the available keyboard path and captures a framebuffer screenshot. `run bios --shell --poweroff-proof` injects `poweroff` and requires QEMU to terminate from the guest's ACPI S5 request. `run bios --shell --network` additionally starts the Rust repository endpoint; the kernel performs a bounded DHCP discover/request/ack exchange before installing the external e1000 service, and `net` reads the resulting address, mask, gateway, DNS, server, lease, and source through `SYS_NET_INFO`. `net interfaces` reads every DHCP-ready NIC and the manager's default route through `SYS_NET_INTERFACES`; `net renew` sends a DHCPREQUEST with `ciaddr` through every managed driver and reports the renewed lease; `net probe` sends the repository request through the selected kernel backend and validates an `RREP3` response. `ls` and `ps` consume bounded kernel snapshots of the recursive runtime filesystem and live-process state; `hw` consumes the PCI/framebuffer/graphics capability snapshot through `SYS_HW_INFO`. `touch`, `mkdir`, `write`, `append`, `truncate`, `rm`, and `mv` use disk-backed paths only within `/home/user`, including normal names such as `documents/meeting-notes.txt`; `grow` writes and reads back a 128 KiB file through one open handle, while `append` exercises `SEEK_END`, `truncate` shrinks and re-extends the FAT file with zero-filled new bytes, `mv`/`rm` exercise persistent directory-entry lifecycle, and `open-proof` verifies a second open observes shared size changes while an existing descriptor survives rename, unlink, detached writes, and final close. `sudo pkg ...` and `sudo state set` are the supported privileged shell operations. The shell-mode runtime gate requires process, file, and hardware snapshots, user-home persistence, long-name create/lookup/readback, seek/append and truncate/extension, large-file growth/readback, rename/read/remove, open-descriptor lifecycle, protected-file readback, denied system writes, real input bytes, command completion, PID 1 reaping, and a clean system status.
`run bios --shell --msi --keyboard-proof` selects Q35 and QEMU's MSI-capable e1000e device. It proves conventional PCI capability discovery, one-vector 64-bit MSI-X table programming to the local APIC, interrupt-driven e1000 loopback, and DHCP/external UDP; ordinary BIOS/UEFI shell runs retain the complete keyboard proof, while ordinary PCI devices retain MSI and ACPI legacy IO-APIC fallbacks when MSI-X is unavailable.
`run bios --shell --ahci --network --keyboard-proof` selects Q35's PCI AHCI controller and proves a bounded AHCI IDENTIFY/READ/WRITE/FLUSH path, FAT/VFS boot-file loading, persistent `/RUSTOS.ST` readback, and shell reachability through the modern SATA transport; AHCI command completion uses PCI MSI/MSI-X with a polling fallback, and legacy ATA PIO remains the fallback when no AHCI controller is present. `run bios --shell --ahci-interrupt-proof` and `run uefi --shell --partitioned --ahci-interrupt-proof` additionally require the AHCI PCI MSI capability, nonzero completion interrupts, and a ready FAT/VFS probe; the UEFI variant verifies the GPT/FAT32 path.
`run bios --shell --nvme --network --keyboard-proof` selects QEMU's PCI NVMe controller and proves bounded admin/I/O queue setup, controller and namespace IDENTIFY, PRP-backed READ/WRITE/FLUSH, FAT/VFS boot-file loading, persistent `/RUSTOS.ST` readback, DHCP, and shell reachability through the NVMe transport. `run bios --shell --nvme-interrupt-proof` and `run uefi --shell --partitioned --nvme-interrupt-proof` additionally require the NVMe PCI MSI-X capability, a nonzero interrupt count from admin and I/O completions, and a ready FAT/VFS probe; the UEFI variant verifies the GPT/FAT32 path. AHCI and ATA remain fallback transports when NVMe is unavailable.
`run bios --shell --virtio-network-proof` attaches modern virtio-net plus MSI-capable e1000e to separate QEMU user-network backends. It requires both Rust drivers to complete initialization and DHCP, then proves the virtio MSI-X queue vector delivered interrupts, the network manager retains two interfaces, selects `virtio0` as the default route, exposes both records through `SYS_NET_INTERFACES`/`net interfaces`, renews both leases through `SYS_NET_RENEW`/`net renew`, and drives `net probe` through the selected virtio path. The proof requires `SYS_NET_INFO`, `SYS_NET_SEND`, `SYS_NET_RECEIVE`, the renewal report, a nonzero virtio interrupt count, and an `RREP3` repository readback before QEMU exits. The corresponding `run uefi --shell --partitioned --virtio-network-proof` variant keeps the virtio interface and proves the same interrupt-backed manager, renewal syscall, and repository path on the GPT/FAT32 root carrier.
`run bios --shell --vm-proof` and `run uefi --shell --partitioned --vm-proof` boot the filesystem-backed `/bin/vm` workload and require successful writable anonymous mappings, volatile page write/readback, fork cloning, parent-side `waitpid`, unmapping, exact virtual-range reuse through `SYS_MMAP`/`SYS_MUNMAP`, and process address-space reclamation after the shell exits; the UEFI variant additionally verifies the GPT/FAT32 root carrier.
`run bios --smp 2 --smp-proof` and `run uefi --partitioned --smp 2 --smp-proof` require a complete two-vCPU runtime handoff: both MADT processors must start, the BSP must deliver local-APIC timer preemption and scheduler activity, the BSP must release the AP scheduler loop before the process gate, and at least one filesystem-backed ring-3 process must report execution on the non-BSP AP before RustOS reaches interrupt-driven idle. Per-CPU TSS/GDT, current-process state, CR3 selection, process placement, and timer preemption are all covered; the proof still scopes concurrency to the supported bounded scheduler rather than claiming broad hardware scalability.
`run bios --shell --usb --keyboard-proof` attaches QEMU's PCI xHCI controller and a USB HID keyboard. The kernel resets the host controller, allocates a 4 KiB command/event/transfer-ring set, resets the connected root port, enables and addresses one slot, reads device and configuration descriptors through control TRBs, configures the boot-keyboard interrupt-IN endpoint, arms the controller's PCI MSI-X interrupt, and proves real DMA-backed HID reports by feeding the injected `net` and `exit` commands through USB. The final diagnostic records the selected vector and nonzero xHCI interrupt count; MSI is the fallback when MSI-X is unavailable, and PS/2 remains available when no xHCI HID keyboard is ready.
`run bios --shell --usb-legacy --keyboard-proof` disables QEMU xHCI MSI and MSI-X, routes the controller's PCI interrupt line through the ACPI-described IO-APIC, and proves real interrupt-driven USB keyboard reports through the shared device-vector handler. The final diagnostic records `mode=Legacy`, the resolved GSI, and a nonzero xHCI interrupt count. The same proof works through `run uefi --shell --usb-legacy --partitioned --keyboard-proof`; the UEFI variant additionally verifies the GPT/FAT32 root carrier.
`run bios --shell --poweroff-proof` and `run uefi --shell --partitioned --poweroff-proof` discover the ACPI FADT and DSDT `_S5_` package, expose the validated PM1 control block through `SYS_POWEROFF`, and write the firmware-provided sleep type plus `SLP_EN` to request an ACPI shutdown. The proof accepts only a guest-owned QEMU exit; the runner does not send a monitor `quit` command.
`run bios --shell --reboot-proof` and `run uefi --shell --partitioned --reboot-proof` discover the FADT reset-register Generic Address Structure, expose it through `SYS_REBOOT`, and write the firmware-provided reset value. The proof accepts only a guest-owned reset terminating under QEMU's `-no-reboot` policy.
`run bios --shell --suspend-proof` and `run uefi --shell --partitioned --suspend-proof` discover the FADT/DSDT `_S3_` contract and validated FACS, expose ACPI S3 through `SYS_SUSPEND`, copy legacy and native wake entries into low memory, and write the standard CMOS S3-resume status before requesting `SLP_TYP` plus `SLP_EN`. When the FACS is ACPI 2.0 with both firmware and OSPM 64-bit-wake support, RustOS publishes the extended vector: it patches the live saved CR3 into the low-memory native entry, restores the RustOS GDT after loading CR3, and jumps directly into the existing long-mode re-entry path. SeaBIOS and legacy OVMF FACS layouts retain the 16-bit-to-long-mode vector as the conservative fallback. The runner requires QEMU to enter `suspended`, accept `system_wakeup`, return to `running`, and RustOS itself to print `power: ACPI S3 resume status=ready` followed by `suspend: resumed`. `RUSTOS_QEMU=/path/to/qemu-system-x86_64 cargo run -p rustos-xtask -- run uefi --shell --partitioned --suspend-proof --native-suspend-proof` additionally requires the serial `vector=native` marker for a firmware/QEMU build that advertises the ACPI 2.0 64-bit wake contract.
`run bios --shell --audio-proof` attaches QEMU's Intel 82801AA AC'97 model to its WAV backend, waits for the Rust driver to publish `audio: ac97 ... rate=48000 ... status=ready`, lets the 32-page DMA tone drain, and verifies a stereo PCM WAV with nonzero samples. The guest driver uses only Rust PCI I/O-port and DMA paths; QEMU's host-side input-voice notices are harmless because the proof exercises playback only.
`run bios --shell --hda-audio-proof` attaches QEMU's ICH9 Intel HDA controller and an `hda-output` codec to the WAV backend, resets the controller, discovers the codec topology with immediate verbs, routes a DAC to an output-capable pin, waits for `audio: hda ... rate=48000 ... status=ready`, lets the 32-page DMA tone drain, and verifies a stereo 48 kHz PCM WAV with nonzero samples. The guest driver uses only Rust PCI MMIO, codec verbs, and DMA paths; AC'97 is not allowed to satisfy this proof.
`run bios --desktop --terminal-proof` and `run uefi --desktop --partitioned --terminal-proof` type `help` through the focused `/bin/terminal` client, require the redirected shell output marker, and send `exit` through the same pipe-backed input path. `run bios --desktop --usb-mouse --desktop-proof` attaches a boot-protocol USB HID mouse and boots the separate Rust desktop session. `run bios --desktop --usb-both --desktop-proof` attaches both a USB keyboard and mouse to one xHCI controller; the kernel enumerates two directly connected root-port devices, shares one event ring, arms MSI-X, routes completions by slot and endpoint after interrupt notification, and preserves mouse events while the console or desktop consumes keyboard bytes. `run bios --desktop --usb-hub --desktop-proof` attaches one static USB 2 hub at xHCI root port 1 and places the keyboard and mouse behind hub ports 1 and 2. `run bios --desktop --usb-hotplug --desktop-proof` starts with that hub and keyboard, adds a QEMU USB mouse to hub port 2 through the monitor, proves bounded downstream attach and HID report delivery, then removes the device and proves slot disable/detach. `run bios --desktop --usb-nested --desktop-proof` adds a second hub behind the first and places the keyboard and mouse behind inner-hub ports 1 and 2; the kernel recursively enumerates hubs, preserves each immediate parent context, composes xHCI route nibbles (`0x11` and `0x21`), and fills the parent-hub slot fields. `run bios --desktop --usb-nested-hotplug --desktop-proof` starts with the two hubs and keyboard, adds/removes the mouse behind the inner hub, and proves the same route-aware attach, HID report, pointer-event, and slot-disable path. The transfer-ring link phase is exercised by repeated empty-port scans. These layouts report the first decoded HID packet before `/bin/desktop` receives it through `SYS_INPUT_READ`; the compositor composes two filesystem-backed ring-3 clients in an explicit bottom-to-top stack, raises the clicked surface, routes focused keyboard input to the last raised client, and owns title-bar drag, bounded resize, close-request delivery, and child reaping policy. The proof logs primary movement/configure, secondary resize/configure, secondary keyboard focus, close handling, and client reaping; the screenshot shows both retained surfaces after the move and resize. The static and hotplug nested proofs also work through `run uefi --desktop --usb-nested --partitioned --desktop-proof` and `run uefi --desktop --usb-nested-hotplug --partitioned --desktop-proof`, and the existing paired-device proofs retain their BIOS/UEFI coverage. The UEFI path additionally verifies the GPT/FAT32 root carrier. `--usb` remains the keyboard-specific xHCI proof. This is a native desktop-session foundation, not yet a Wayland protocol implementation; isochronous endpoints, SuperSpeed devices, and raster GPU acceleration remain future work.
`run uefi --shell --partitioned --network --keyboard-proof` boots the partitioned shell variant. The Rust builder creates a GPT with an 11 MiB EFI System Partition and a default 64 MiB FAT32 RustOS root partition; `--root-mib N` selects a larger aligned root from 64 MiB through 128 GiB, so `build --root-mib 4096`, `install ... --partitioned --root-mib 4096`, and `run ... --root-mib 4096` produce a usable multi-gigabyte installation without changing the kernel's root-volume selection. UEFI loads the bootloader and kernel from the ESP, while the kernel selects the FAT32 root volume for `/RUSTOS.ST`, `INITRD.CPI`, and the runtime catalog. The proof performs DHCP configuration, reads the lease through `net`, injects keyboard input, and toggles `/RUSTOS.ST`; rebooting the same image verifies the persisted toggle in the FAT32 root.

The framebuffer remains attached for the life of the kernel instead of being painted once at boot. Rust serial output is mirrored into an embedded Noto Sans Mono text terminal with bounded line wrapping, scrolling-by-clear, backspace, and control-character handling; fd 0 polls the 16550 UART, up to two PCI xHCI HID devices (direct root-port devices or children behind nested static hubs), and the i8042 PS/2 decoder as fallback. `SYS_INPUT_READ` drains the shared xHCI HID queue only after MSI-X/MSI completion notification, then falls back to PS/2 pointer data when a USB mouse is present. The graphics ABI exposes framebuffer geometry, single-process ownership, clipped color rectangles, bounded text rendering, retained window surfaces, an explicit window stack, and hit-tested client event queues to ring-3; `SYS_INPUT_READ` exposes bounded mouse and keyboard events, while the window dispatch/read ABI raises clicked surfaces, routes pointer plus focused keyboard events, and lets the compositor configure or close client windows. The desktop session suppresses kernel log mirroring after acquisition so its scene remains stable. `/bin/terminal` uses a nonblocking pipe-read ABI and parent-stream inheritance to keep a Rust shell interactive inside a focused retained window. BIOS and partitioned-UEFI boots prove `help` output and shell exit through QEMU keyboard injection, while the USB HID desktop proofs capture the same framebuffer after separate userland window rendering, click-to-raise focus changes, title-bar movement, resize, focused keyboard delivery, client close/reap, and bounded runtime USB attach/detach.

The same run also reports the FAT root carrier, signed `/RUSTOS.REP` repository, initramfs size and entry count, nested `/etc/rustos/config.txt` metadata, and a non-executable `data_reads=1` count for each child. BIOS and UEFI runs exercise the archive through MBR and GPT images respectively.

The BIOS and UEFI process proofs also require the service's same-PID image replacement, the restart failure/recovery pair, and all seven registered processes to exit with the expected statuses before the system enters its interrupt-driven idle state. Shell-mode BIOS and UEFI boots additionally prove Ed25519 repository verification, dependency activation, nested runtime listing, payload readback, and persistence across reboot.

`run bios --recovery` and `run uefi --recovery` boot a separate recovery image with a `recovery:/home/user#` prompt. The image carries a recovery marker and, when package state exists, attempts `pkg recover` before accepting commands; a clean image remains usable for an initial installation. The installer writes that complete boot image to the requested target, verifies it, and `run ... --image TARGET` boots the installed artifact directly. `install uefi TARGET --partitioned` extracts the verified ESP and FAT32 root from the selected artifact, writes a new GPT to the requested regular file or block device, and verifies both partition hashes before reporting `repartition=ready`; `--root-mib N` is carried through the source image, repartitioning, and installed-image boot proof. UEFI NVRAM boot-entry enrollment, user-selected ESP layouts, and filesystem provisioning beyond the RustOS ESP/root layout remain future installer work.

The strict desktop proof now requires the native compositor, focused terminal and secondary clients, a live `SYS_LIST_FILES` storage snapshot, and a valid captured framebuffer on BIOS and partitioned UEFI. The secondary client renders the catalog and refreshes it when focused input sends `R`; the separate logout proof verifies that the graphical `LOG OUT` control returns ownership to the login boundary.

The login/session proof now covers first-boot username/password setup without a shipped default credential, writable account-store bootstrap and reread, `/bin/passwd` password mutation, administrator-password-checked `sudo useradd` account creation with explicit role selection, graphical password masking, `/bin/lock` retry/unlock behavior, per-UID home isolation, old-password rejection, new-password relogin, non-administrator privileged denial, persistent reload on a second BIOS and partitioned-UEFI boot, two authenticated desktop sessions, graphical logout, and clean client reap. The separate role proof creates a secondary administrator, authenticates it as UID/GID 1001, and verifies that its password authorizes a fixed privileged operation. Preseeded installer profiles, richer group authorization, and broader multi-user policy remain explicit replacement milestones.

## What “rebuild CachyOS” means here

The target is a bootable, Rust-owned operating system and distribution: kernel, hardware abstraction, drivers, init, services, package/store format, installer, shell, and desktop plumbing. CachyOS compatibility and performance are acceptance goals, not a license to call a small demo a finished distro. The roadmap records the dependency order.
